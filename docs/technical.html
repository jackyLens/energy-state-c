从五路信号到一条能量曲线

这个 C 库把智能戒指的心率、HRV、睡眠分期、步数与压力，变成一条 5 分钟粒度、0–100 的能量曲线，附带每日汇总与睡眠恢复报告。本文说明它的数据流、模型、接口与验证边界。

01

输入到输出：一条单向数据流

整条链路是单向的：观测只通过滤波器反哺状态，不回写模型；离线拟合的参数按天/周批量下发。七个阶段各司其职，任何一个阶段的缺失都在下一阶段被显式标注，而不是被插值掩盖。

02

输入契约：哪些必须由外部给

只有 t_h 是绝对必须。stage 与 hr 决定“这是不是一个能量模型”：没有分期，夜里不充电；没有心率，滤波器退化为开环。其余字段都有默认值或由库内部计算。

档位字段作用不传时
必须t_h时间轴，严格递增无法计算
必须stage[4]睡眠分期 → m / λ / ψ，决定夜里充多快m=0，全程清醒：07:00 的 E 从 0.71 掉到 0.37
必须hr主观测通道 + 负荷 TRIMP退化为开环，只剩先验，置信带宽 = 0
建议hrv_log第二观测通道（夜间信息最大）只剩 HR 校正
建议steps_5m负荷 L 与活动量 A 的主要来源L 只由 HR 算；HR 也缺则 L=0
建议stressβ_P 消耗项（满量程 ≈ 3×β0）少一项消耗，能量略偏高
建议tod节律、日间观测窗口、基线分箱按 t_h % 24 推断；起点非 00:00 会错位
建议q_hr / q_hrv伪迹、摘表时关掉该点默认 1（全部相信）：+6 bpm 偏差可把 E 拉偏 0.36
可选kcal只影响活动量 AA 只由步数算
可选load / activity上游已算好时直接传库内部按固定规则计算
初始化用 energy_sample_init()，不要 memset(0)。 0 会把 q 当成“无效观测”而跳过滤波，把 hr 当成 0 bpm。

配置层比字段更影响质量

  • cfg.obs：离线拟合的观测模型（最重要）
  • cfg.params：个体化状态参数
  • cfg.load.l_ref：用户画像固定值，跨窗口可比
  • cfg.x0：接续计算时传上次末状态

三个最常见的集成错误

  • 把 hrv_log 填成毫秒（45 而不是 3.81）
  • 白天把 stage[wake] 设成 1（会走夜间方程）
  • 一半字段传、一半让库算（归一化路径不同）
03

能量收支：两个状态，一个充放循环

能量 E 不是被“测量”出来的，而是由睡眠充电与清醒消耗共同推出来的。睡眠结构决定充电效率，活动与压力决定放电速度；S（睡眠压力）既是充电的驱动，也是白天的额外消耗。

把两段方程合起来就是一个有界系统：S 的向量场永远指向 [0,1] 内部，E 的平衡点 α/(α+β) 也落在 [0,1]。因此实现里不需要“事后截断”，只有滤波器更新后的一次数值保护。

/* 单步闭式推进（不是欧拉法） */
S∞ = a / b;            S(t+h) = S∞ + (S − S∞) · e^(−b·h)
E∞ = α / (α + β);      E(t+h) = E∞ + (E − E∞) · e^(−(α+β)·h)

参数默认依据证据强度

κ_s deep/light/rem0.42 / 0.26 / 0.18深睡消散最快，τ = 2.4 / 3.8 / 5.6 h；只约束序关系弱

不要把单个参数当“个人恢复能力”展示。 11 个参数里只有 5 个有清晰剖面峰；其余是平坦方向。要展示的是它们组合出的可观测量：充电 τ、消耗 τ、8 小时睡眠的 ΔE。
04

观测与滤波：心率是校正，不是能量

HR/HRV 不直接变成能量。它们是“身体对当前状态的反应”，通过夜间与日间两套线性观测方程，进入一个 2×2 的扩展卡尔曼滤波。一次更新只移动一点点——平均增益约 1e-3，所以曲线主要由状态方程决定。

通道夜间方程日间方程
HR58 − 12·E − 5·p_deep + 2·p_rem + 9·p_wake80 − 12·E + 105·A + 谐波
ln RMSSD3.55 + 0.45·E + 0.30·p_deep + 0.18·p_rem − 0.35·p_wake3.25 + 0.45·E − 0.55·A + 谐波

四道稳健化

  • Student-t(ν=4)：大新息自动降权
  • 4σ 门控：单点伪迹不参与更新
  • 质量位 q：R = σ² / max(q, 0.05)
  • Joseph 形式：长期运行协方差不发散

一个必须知道的脆弱点

  • 持续性心率偏移（+9 bpm）会被当成“能量低”
  • 4σ 门控挡不住：它只看单点
  • 对策：异常夜冻结观测（q=0）后重跑
  • 不做这一步，测试段 RMSE 从 0.045 升到 0.13
05

两种用法：整段回放，或每五分钟一步

批量接口适合离线回放、补数据与回归测试；流式接口适合在线设备。两者共用同一套子函数，状态逐点一致——差别只在流式不做展示层的 30 分钟居中平滑。

/* 批量：整段回放，出曲线 + 日汇总 */
energy_output_t out = {0};
energy_compute(samples, n, &cfg, &out);
printf("%.1f", out.points[i].energy);
energy_output_free(&out);

/* 流式：每 5 分钟一步，状态在调用方手里 */
energy_ctx_t ctx;  energy_ctx_init(&ctx, &cfg);
energy_point_t p;
energy_ctx_step(&ctx, &sample, &p);   /* p.energy = 0–100 */
06

生命周期与错误：从不假装“已就绪”

冷启动时初始协方差故意放大，让前几次观测能把状态拉到位；数据中断时只做预测，置信带变宽；极长缺口让协方差失去意义时，自动回到冷启动方差，而不是永久失聪。

返回码触发条件调用方该做什么
ENERGY_OK正常使用 point.energy
ENERGY_EINVAL空指针、n<2、配置非法、t_h 非有限修参数/配置，不要重试
ENERGY_EDOMAIN时间不递增、单次 step 时间倒退检查排序与时间源
ENERGY_ENOMEM批量接口分配失败减少窗口或稍后重试

08

边界：它不能做什么

没做的

  • 异常夜冻结与二次回放（上层编排）
  • 睡眠 episode 报告与冷启动文案
  • 离线拟合（用 Python 端产出 fit.json）
  • 医学诊断、疾病预警、感染预测

需要外部验证的

  • 0–100 刻度与用户主观能量的对应
  • 参数个体化是否带来样本外增益
  • 不同设备基线下的观测量偏移
  • 轮班、时差、女性周期、药物影响
一句话：它是一条“有结构、有边界、缺数据也能解释”的模型曲线，不是身体电量的测量值。产品文案不能写成“测量/诊断”。
